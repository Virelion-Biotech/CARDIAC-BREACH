# CARDIAC//BREACH

**A browser-based medical roguelike strategy game powered by a hidden synthetic cardiac tissue model.**

The player sees crises, limited interventions, spatial consequences and a collapsing heart. The simulation underneath is deliberately more detailed than the UI exposes. It is a fictional educational/entertainment model, not a biological intervention tool.

## Current player loop

**Crisis → one critical move → end turn → consequence → next crisis**

The player does not need to understand the internal physiology to play. Advanced state remains available for debugging and development, not as mandatory player knowledge.

## Current simulation

The active engine models interacting tissue-level state including:

- cardiomyocyte, fibroblast, endothelial and immune cell populations
- regional traits and spatial neighbor coupling
- perfusion and oxygen delivery
- metabolic/ATP state
- oxidative stress and calcium load
- cellular stress and damage
- immune recruitment and resolution
- repair capacity and recovery
- matrix remodeling and scar burden
- electrical conduction and coupling
- maturation/function
- systemic reserve and organ-level aggregation
- deterministic seeded runs
- local intervention fields with distance decay

The simulation runs in explicit phases and keeps an auditable per-turn state transition. An internal precision ledger tracks selected accounting values at fixed-point 10^-18 resolution for reproducibility and exact signed bookkeeping.

## Architecture

New application code uses native ES modules:

```text
src/bootstrap.mjs
  └─ CardiacAppController
      ├─ game port
      ├─ lifecycle/input ownership
      ├─ save/load
      ├─ render scheduling
      └─ legacy compatibility boundary
```

The established mechanistic engine remains the authoritative rules implementation. `src/core/game-port.mjs` is the supported boundary for modern application code. `legacy-compat.js` is the only compatibility surface for the older IIFE presentation modules.

The retired v2 adapter is no longer loaded by the game. Do not build new consumers against the old v2 API.

## Development

```bash
npm install
npm run check
npm test
npm run build
npm start
```

Open `http://127.0.0.1:4173`.

`npm test` runs unit tests and Playwright browser tests. Browser coverage includes desktop Chromium and mobile Chromium.

## Release

GitHub Pages deploys the reproducible `dist/` build generated by `npm run build`. CI validates syntax, unit tests, browser tests and the build on pushes and pull requests to `main`.

## Engineering rules

Do not add a new global state store, alternate simulation engine, timing-based initialization, or redundant UI subsystem without an architectural justification and tests. Prefer named tuning constants and document the gameplay reason for important balance values.

See [ARCHITECTURE.md](ARCHITECTURE.md) and [CONTRIBUTING.md](CONTRIBUTING.md).

## Safety / scope

CARDIAC//BREACH is a fictional synthetic game model. It does not model real pathogens, provide experimental protocols, or provide actionable instructions for manipulating real biological systems.
